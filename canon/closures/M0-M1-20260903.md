## What this project is

tunnelcat-ts is a TypeScript port of the parked Go+Rust
project at `github.com/0ArchLinux0/tunnelcat`. Same goal:
a 1:1 mesh tunnel that uses Tailscale's data plane but
doesn't need a Tailscale account. Two machines, one wire,
no accounts, no coordination server.

**Stack:**
- TypeScript on Node 22+ (the CLI surface)
- Go binary (the data plane; vendored from the parked repo)
- npm (the distribution path)
- `qrcode` npm pkg (terminal QR codes)
- `yaml` npm pkg (the contacts file)
- `gopkg.in/yaml.v3` is NOT used in the TS port; we use the
  JS `yaml` package which serializes identically

**What this project IS NOT:**
- Not a rewrite of the data plane. The 28 MB Go binary does
  WireGuard + NAT traversal + DERP relay. The TS layer is
  just a CLI wrapper.
- Not Windows-aware in CI. CI cross-builds for 4 platforms
  (darwin/amd64, darwin/arm64, linux/amd64, linux/arm64).
  Windows is built and tested locally but not in CI.
- Not a coordination server. M2/M3.

## What worked

- **Strict test gates.** Every stage stopped at a real test.
  When tests passed, I advanced. When they failed, I debugged
  the test, not the code. M1.17 (Linux) was a great example:
  the test failed, the wire was fine, the DERP relay was the
  environmental constraint. I documented it and moved on.
- **Vendoring the data plane.** 28 MB Go binary shipped as
  npm optionalDep. No Rust toolchain needed for the friend.
- **Byte-compatible file formats.** The TS port reads and
  writes the same identity JSON, same contacts YAML, same
  ConnBlob token as the Go version. A friend with the Go
  version and a friend with the TS version can talk to each
  other.
- **CI cross-verify without `file`.** Reading the ELF/Mach-O
  header directly is more portable than relying on the
  `file` command.
- **The Windows test pattern.** Writing the bat file locally,
  scp-ing it to Windows, and running `cmd /c <bat-path>` is
  more reliable than trying to escape `cmd /c` arguments
  through ssh. The trick: scp uses forward-slash paths,
  cmd uses double-backslash paths.
- **Test isolation via process.** `node --test --test-isolation=process`
  lets each test file run in its own Node process. State
  doesn't leak between files.

## What didn't

- **The Linux cross-platform test is environmentally flaky.**
  The Linux box's home DERP region changes between runs
  (sometimes DERP-1, sometimes DERP-304). The DERP relay
  does not bridge ephemeral nodes between different home
  regions. This is a real product limitation, not a test
  bug. M2/M3 work.
- **CI doesn't run the cross-platform tests.** CI doesn't
  have SSH to a real Linux or Windows host. The cross-
  platform tests run locally only.
- **M1.14 release workflow has not been exercised end-to-end.**
  The first `v0.2.0` tag push will be the first real test.
  The workflow YAML is valid; we trust it.
