## What M2 is (for context, when the user un-parks it)

M2 in the Go version (see `~/code_repo/tailcat/canon/ROADMAP.md`)
is the Rust type-state Meow. It replaces the hand-written
CBOR encoding in the Go data plane with a Rust crate that
encodes the state machine at the type level. The win is
"can't construct an invalid packet" — the compiler
guarantees it.

In the TS port, M2 would be:

1. Replace the vendored `crates/tunnelcat-proto` with a
   clean-room Rust implementation of the wire protocol.
2. Build the helper with cgo cross-compilation (currently
   disabled — see below).
3. Add the M2 features that depend on the type-state:
   - Packet-level encryption (authenticated Meow)
   - More efficient DERP relay use
   - Reduced binary size (no more cgo for the proto crate)

## What M2 is NOT (the user said "no")

- No rewriting the data plane in TypeScript. (The data
  plane stays in Go + Rust; the TS port is just the CLI.)
- No cross-region DERP bridging. (That's M3 — coord server.)
- No macOS DMG / Windows MSI. (That's M5 — polish.)

## Current limitations (deferred to M2/M3)

- The Linux cross-platform test is environmentally flaky
  because the Linux box sometimes picks DERP-1 instead of
  DERP-304, and the DERP relay does not bridge ephemeral
  nodes between different home regions. This is a real
  product limitation. **M2 does not fix it; M3 (coord
  server) does.**
- The helper binary is 28 MB. Most of that is the Go
  runtime + tailscale.com. cgo cross-build with a stripped
  Rust proto could halve this. M2 work.
